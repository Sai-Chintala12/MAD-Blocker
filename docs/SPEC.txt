Smart pop-up management

This is one of the most important features you requested. We don't want to block useful windows just because they open separately from the current page.

How the logic should work

There is an important technical limitation: Chrome does not expose a universal event that lets an extension inspect every attempted pop-up and perfectly determine the user's intention. The extension should use browser-native pop-up protections, user-controlled site permissions, and appropriate navigation or request rules rather than claiming to detect every case.

Site-level controls

Each website should have settings for:

Default: use normal blocking rules.

Allow pop-ups: permit legitimate new windows for this site.

Block more aggressively: apply stricter blocking rules.

Pause CleanFeed: temporarily disable filtering for this site.

A trusted-site list should be editable, and the user should be able to remove a site from it at any time.

6. Security and privacy requirements

The extension itself must not become a security risk.

Mandatory security rules

Request only the permissions needed for its functionality.

Avoid collecting or transmitting browsing history.

Do not collect passwords, cookies, or form data.

Do not execute arbitrary JavaScript downloaded from a remote server.

Validate imported settings and custom rules.

Keep trusted-site exceptions visible and easy to manage.

Use HTTPS for any future filter-list updates.

Review changes to filter lists before releasing updates.

Keep dependencies minimal and regularly maintained.

Never claim that ad blocking replaces antivirus, browser updates, or safe browsing practices.

The extension will need some access to websites to filter their content. We should explain this access clearly to the user instead of requesting unrestricted permissions without a reason.

7. Performance and PC temperature

Performance should be a core design requirement, not something we check only at the end.

Design choice

	

Why it matters




Browser-native request filtering

	

Reduces the need to process each request in JavaScript




Small, efficient filter lists

	

Limits rule-processing overhead




Event-driven service worker

	

Avoids unnecessary background activity




Targeted page cleanup

	

Prevents constant scanning of entire pages




Mutation observers with sensible limits

	

Handles dynamically loaded ads without excessive CPU use




No unnecessary network requests

	

Reduces bandwidth and background activity

We should measure CPU usage, memory usage, page loading time, and video playback performance on your PC. There is no honest way to guarantee a particular temperature without testing on your actual hardware.

10. How we will test it

Before considering the extension ready, we should test the following:

Common banner ads are blocked.
Recognized ad spaces follow the selected black, white, or collapse setting.
Normal links, forms, login windows, and downloads still work.
Unsolicited advertising pop-ups are blocked where detectable.
Trusted-site exceptions work and can be removed.
YouTube playback, seeking, subtitles, and fullscreen work.
Movie and anime websites retain their video controls.
The extension does not collect or transmit browsing history.
CPU, memory, and page-load overhead are measured.
Invalid filter rules and settings do not crash the extension.
Disabling CleanFeed restores normal browser behavior as far as the extension's changes allow.

Final design decisions

Here is the specification I recommend we follow:

Browser

Google Chrome first, with future cross-browser support.

Ad presentation

Black, white, or collapsed ad placeholders.

Pop-ups

Allow intentional pop-ups and configurable trusted-site exceptions; block unwanted ones when detectable.

Performance

Lightweight rules, minimal background work, and measured CPU usage.

Privacy

Local-first settings, minimal permissions, no browsing-history collection.
